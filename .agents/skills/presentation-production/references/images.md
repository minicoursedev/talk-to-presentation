# 圖片製作與更新

本流程處理新插圖、既有圖片編輯與圖片替換；頁面內容與製圖授權沿用既有對話，不新增重複確認關卡。

## 先判定修改範圍

- 新增圖片：依已確認主題、指定頁面及插圖要求製作。
- 圖片內容修改：先查看原圖，確認要改的物件、構圖或風格；只修改指定部分，保留其他已確認元素。
- 顯示位置、裁切、滿版範圍、遮罩或圖層錯誤：修正 HTML／Canvas Commons 的版面來源，沿用原圖。不要因顯示錯誤重製圖片。
- 一般重建沿用既有圖片；只有使用者要求製圖或更新圖片內容，才執行圖像生成／編輯。

## 製作圖片

1. 讀取指定頁的 `slides.json` 與 `visual.notes`，查看同案既有圖片及實際版面，掌握風格、尺寸比例、主體位置、文字留白區與裁切焦點。未指定的視覺細節沿用同案設計，不自行改變整套風格。
2. 新製或編輯點陣插圖時使用可用的 ImageGen 工具，並遵循適用的 imagegen skill。編輯時提供原圖作為參考；既有 SVG 或程式繪圖則修改其來源，不必轉成生成圖片。
3. 提示詞以已確認內容為準，列明畫面比例、主體與文字區位置。除非使用者指定文字應在圖中，標題、字幕、頁碼與品牌由 HTML／影片圖層呈現，避免烘焙進插圖而無法同步修改。
4. 查看生成結果並以目標畫布預覽裁切，確認指定內容、風格、主體完整性及文字區可用。若需要分層動畫，準備實際獨立圖層／資產，不把單張完成圖裁切當成分層製作完成。

## 保存與同步

- 圖片存於案件 `assets/illustrations/`；替換時保留原圖，用可辨識的新檔名保存新版，避免覆寫後失去對照依據。
- 更新受影響頁的 `slides.json[].visual.illustrations` 引用與必要的 `visual.notes`，在 `content/draft.md` 記錄指定頁、修改要求、資產路徑與確認狀態。生成成功不代表使用者已確認。
- HTML 與影片讀取同一份更新後的資產引用。圖片變更不重製旁白，也不修改高橋流文字。若改動 `slides.json` 或 `case.json`，先用既有 WAV 執行 `voice.py timeline` 刷新來源雜湊，再 prepare 與渲染；這不呼叫 TTS，未變更 WAV 與 timing 設定時，影片時長不變。
- 若美化 HTML 已正確、只有影片顯示錯誤，只修正影片並重建影片。

## 驗證

- 實際查看新圖，以及它在美化 HTML 和正式影片中的呈現；核對引用的是新版、滿版／裁切與文字位置一致，沒有額外遮罩或品牌遮蔽。
- 檢查全部修改頁，包含使用者指出的問題頁；影片依影片流程先局部驗證再輸出全片。
- 交付時列明更新頁碼、圖片路徑、已重建產物及尚未確認項目。不得以圖片已生成，代替 HTML／影片已更新並驗證。

## 逐頁規劃與覆蓋要求

先讀完整主題，再在每頁 `visual.notes` 記錄「這頁在說什麼 → 圖中要看見的物件／關係 → 構圖與文字留白」。同時讀取案件選定的風格參考與代表頁；依該頁語意決定物件、場景與關係，以共同視覺語言維持連貫。

視覺美化與敘事補充是兩個維度。標題、提問或結尾頁未必需要新情節，仍須完成約定的視覺設計；使用者要求每頁有圖時，這些頁也不能省略。未要求全頁插圖時，不自行把它升格為所有案件的固定規則。只在既有指示無法判定且會影響交付時，釐清圖片覆蓋範圍。

要求每頁有圖時，在該案件 `case.json` 加入 `"visual": {"requireImages": true}`，於大量製圖前記錄需求，重建美化 HTML 與準備影片時就會阻擋缺圖。亦可單次檢查：

```bash
node "$PROJECT_ROOT/tools/check-visuals.mjs" my-talk --require-images
```

工具檢查頁碼、引用、檔案存在與非空，回報有圖頁數及無圖頁碼；目前 HTML 只呈現 `illustrations[0]`。檔案存在不代表圖片能解碼、切題或文字可讀，仍需逐頁查看。重複資產可以是刻意設計；只有另有「每頁不同圖片」要求時才需逐頁獨立資產。已授權生成時，逐頁規劃是執行依據，不是新增確認關卡。
