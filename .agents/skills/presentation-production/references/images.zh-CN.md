# 图片制作与更新

本流程处理新插图、既有图片编辑与图片替换；页面内容与制图授权沿用既有对话，不新增重复确认关卡。

## 先判定修改范围

- 新增图片：依已确认主题、指定页面及插图要求制作。
- 图片内容修改：先查看原图，确认要改的物件、构图或风格；只修改指定部分，保留其他已确认元素。
- 显示位置、裁切、满版范围、遮罩或图层错误：修正 HTML／Canvas Commons 的版面来源，沿用原图。不要因显示错误重制图片。
- 一般重建沿用既有图片；只有用户要求制图或更新图片内容，才执行图像生成／编辑。

## 制作图片

1. 读取指定页的 `slides.json` 与 `visual.notes`，查看同案既有图片及实际版面，掌握风格、尺寸比例、主体位置、文字留白区与裁切焦点。未指定的视觉细节沿用同案设计，不自行改变整套风格。
2. 新制或编辑点阵插图时使用可用的 ImageGen 工具，并遵循适用的 imagegen skill。编辑时提供原图作为参考；既有 SVG 或程序绘图则修改其来源，不必转成生成图片。
3. 提示词以已确认内容为准，列明画面比例、主体与文字区位置。除非用户指定文字应在图中，标题、字幕、页码与品牌由 HTML／视频图层呈现，避免烘焙进插图而无法同步修改。
4. 查看生成结果并以目标画布预览裁切，确认指定内容、风格、主体完整性及文字区可用。若需要分层动画，准备实际独立图层／资产，不把单张完成图裁切当成分层制作完成。

## 保存与同步

- 图片存于案件 `assets/illustrations/`；替换时保留原图，用可辨识的新档名保存新版，避免覆写后失去对照依据。
- 更新受影响页的 `slides.json[].visual.illustrations` 引用与必要的 `visual.notes`，在 `content/draft.md` 记录指定页、修改要求、资产路径与确认状态。生成成功不代表用户已确认。
- HTML 与影片读取同一份更新后的资产引用。图片变更不重制旁白，也不修改高桥流文字。只改画面或图片时沿用时间轴；若同时修改页序或时间设置，再用既有 WAV 执行 `voice.py timeline` 更新时间轴。
- 若美化 HTML 已正确、只有视频显示错误，只修正视频并重建视频。

## 验证

- 实际查看新图，以及它在美化 HTML 和正式视频中的呈现；核对引用的是新版、满版／裁切与文字位置一致，没有额外遮罩或品牌遮蔽。
- 检查全部修改页，包含用户指出的问题页；视频依视频流程先局部验证再输出全片。
- 交付时列明更新页码、图片路径、已重建产物及尚未确认项目。不得以图片已生成，代替 HTML／视频已更新并验证。

## 逐页规划与覆盖要求

先读完整主题，再在每页 `visual.notes` 记录「这页在说什么 → 图中要看见的物件／关系 → 构图与文字留白」。同时读取案件选定的风格参考与代表页；依该页语意决定物件、场景与关系，以共同视觉语言维持连贯。

视觉美化与叙事补充是两个维度。标题、提问或结尾页未必需要新情节，仍须完成约定的视觉设计；使用者要求每页有图时，这些页也不能省略。未要求全页插图时，不自行把它升格为所有案件的固定规则。只在既有指示无法判定且会影响交付时，厘清图片覆盖范围。

要求每页有图时，在该案件 `case.json` 加入 `"visual": {"requireImages": true}`，于大量制图前记录需求，重建美化 HTML 与准备影片时就会阻挡缺图。亦可单次检查：

```bash
node "$PROJECT_ROOT/tools/check-visuals.mjs" my-talk --require-images
```

工具检查页码、引用、档案存在与非空，回报有图页数及无图页码；目前 HTML 只呈现 `illustrations[0]`。档案存在不代表图片能解码、切题或文字可读，仍需逐页查看。重复资产可以是刻意设计；只有另有「每页不同图片」要求时才需逐页独立资产。已授权生成时，逐页规划是执行依据，不是新增确认关卡。
